# Общая служба Tandem

Десктопные клиенты не запускают отдельные серверы и не запрашивают IP друга.
Один публичный сервер нужен для регистрации, уникальных ID, заявок, статусов
и первоначального обмена WebRTC offer/answer/ICE. Сам сервер не принимает видео
и не исполняет удалённые команды. После установки соединения видео, управление
и смена ролей работают по зашифрованному каналу между участниками.

В этой версии публичный сервер ещё НЕ развёрнут. `service.json` намеренно
содержит `null`: нет выдуманного адреса или молчаливого запуска localhost.
До размещения службы можно проверять резервный режим прямых приглашений.

## Разместить на VPS

Требуется Linux VPS с Docker Compose, постоянным диском и доменом, который
указывает на VPS. Для службы достаточно открыть входящие TCP 80/443.
Настройка этого сервера не изменяет NAT или брандмауэр на игровых ПК.

Из клона репозитория:

```sh
TANDEM_DOMAIN=tandem.your-domain.example docker compose -f deploy/compose.yaml up -d --build
curl https://tandem.your-domain.example/health
```

Caddy выдаёт TLS-сертификат и обслуживает WSS. Том `tandem-data` хранит
`accounts.sqlite` (аккаунты и хеши токенов) и `contacts.json` (дружба и заявки,
включая офлайн-доставку). Сохраняйте резервные копии этого тома; его удаление
теряет ID. Не запускайте несколько экземпляров сервера на одном JSON-файле.

Затем установите в `deploy/service.json` в ветке main:

```json
{"server":"wss://tandem.your-domain.example"}
```

Клиент получает этот небольшой конфиг из этого GitHub-репозитория при старте.
После изменения достаточно перезапустить клиент; перестраивать EXE не требуется.
Резервно адрес может быть записан разработчиком в `app/service.json` до сборки
или в `service.json` в папке данных клиента. Обычный интерфейс не предлагает
пользователю вводить адрес. `TANDEM_SERVICE_URL` предназначена для разработки.

## NAT и TURN

HTTPS/WSS-сервер обеспечивает поиск и установление связи, но не гарантирует
прямой UDP при symmetric NAT/CGNAT. При таких сетях нужен отдельный TURN ближе
к пользователям. Это резервный транспорт, а не обычный путь для видео.
Пример настроек — `turnserver.conf.example`; указывайте свой TURN в расширенных
настройках. Секрет TURN не включается в публичный конфиг GitHub.

Нельзя обещать, что любой прямой путь быстрее VPN: важен фактически выбранный
маршрут. Клиент показывает P2P/TURN, транспорт, RTT, потери и обработку кадров.
