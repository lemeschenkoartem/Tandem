TANDEM 0.4.0 — WINDOWS 10/11 x64

1. Обновите оба клиента. Полностью распакуйте ZIP и запустите Tandem.exe из папки
   вместе с ресурсами. Не переносите один EXE отдельно. Node.js не нужен.

2. В обычном интерфейсе нет IP хоста. Каждый из вас может показывать свой экран.
   Поиск по ID и друзья используют одну общую службу Tandem.

ВАЖНО: публичная служба пока не развёрнута. До её размещения поиск и регистрация
через интернет не работают. Это не ошибка вашего ID. Сервер готов к размещению;
инструкция: https://github.com/lemeschenkoartem/Tandem/blob/main/deploy/HOSTING.md
Адрес общей службы будет задан один раз для всех клиентов, без ручного IP друга.
После размещения службы перезапустите клиент. Старые ID из отдельных локальных
серверов не становятся глобальными: общая служба должна хранить общую базу аккаунтов.

3. ПОСЛЕ РАЗМЕЩЕНИЯ СЛУЖБЫ
   - В «Мой аккаунт» войдите или зарегистрируйтесь; получите ID из 8 цифр.
   - В «Друзья» найдите ID друга и отправьте заявку.
   - Друг принимает её во «Входящих заявках»; вы появляетесь в списках друг друга.
   - У друга в сети нажмите «Подключиться». Он подтверждает просмотр и выбирает
     монитор. Управление клавиатурой/мышью разрешается отдельно.
   - Любой из вас может быть хостом; «Показать мой экран» меняет роли с согласия.

4. РЕЗЕРВНЫЙ РЕЖИМ ДЛЯ ПРОВЕРКИ БЕЗ СЛУЖБЫ
   - На странице игры раскройте «Прямая связь по приглашению».
   - Хост создаёт приглашение, выбирает монитор, сохраняет файл .tandem другу.
   - Друг открывает приглашение и нажимает «Найти аккаунт» (будет распознано прямое
     приглашение без входа), сохраняет ответ и отправляет хосту.
   - Хост открывает ответ, применяет его и подтверждает просмотр.
   - Через Tailscale оставьте маршруты VPN разрешёнными. При сложном NAT нужен TURN;
     отсутствие VPN само по себе не гарантирует соединение или меньший RTT.

5. КАЧЕСТВО
   По умолчанию — авто, пределы 1080p, 120 FPS, 60 Мбит/с. Начало до 1080p/60/30,
   затем приложение повышает качество при достаточном запасе сети и обоих ПК.
   Следит за потерями, ростом RTT/очередей, кодированием и декодированием. Быстро
   снижает битрейт при перегрузке, затем FPS/разрешение до выбранного минимума.
   Восстановление постепенное. Автоматические изменения не перезаписывают ваши
   сохранённые пределы. Для сравнения остаётся ручной режим.
   По умолчанию авто держит минимум Full HD. В настройках можно разрешить HD.
   Если вручную выбран HD, выше HD приложение не поднимается. При канале, который
   не тянет этот минимум, идеальной картинки и нулевой задержки обещать нельзя.
   Авто начинает с H.264, пробует H.265/AV1 только если браузеры обоих ПК сообщили
   подходящую аппаратную поддержку. Это не гарантирует NVENC. Есть диагностика.
   Ethernet предпочтительнее Wi-Fi. 144–240 FPS и 4K зависят от захвата, монитора,
   Windows, драйверов и сети. Нативного NVENC-конвейера в этой версии нет.

6. КЛАВИШИ И СОГЛАСИЕ
   Ctrl+F12 — выйти из полного экрана. Esc — отпустить захват мыши.
   Ctrl+Alt+F12 у владельца — немедленно отозвать управление.
   Друг видит весь выбранный монитор, включая открытые окна.
   Дружба не даёт автоматического просмотра или управления.
   При потере связи нажатия отпускаются. Античит/защищённый экран/права игры могут
   блокировать ввод. Геймпады пока не поддерживаются.

7. ЛОКАЛЬНЫЕ ФАЙЛЫ
   В «Качество и сеть» нажмите «Открыть папку данных».
   settings.json — настройки; friends-<сеть>-<ID>.json — друзья и заявки;
   account.json — ID/имя; sessions.enc — защищённый ключ входа Windows.
   Пароли в JSON не записываются. Ключ входа живёт до 30 дней и отзывается выходом.
   При недоступном защищённом хранилище ключ не сохраняется открытым текстом.
   TURN-пароль в этой версии действует только в текущем запуске.

8. ДИАГНОСТИКА
   «Скопировать диагностику потока» показывает P2P/TURN, транспорт, настоящий кодек,
   обработку кадров, фактический битрейт и решения автоподбора. RTT — время сети
   туда и обратно, не полная задержка управления. Реальные Windows GPU и NAT
   ещё нужно проверить на ваших ПК. Проверки Linux используют loopback TURN/TCP.

Исходники и релизы: https://github.com/lemeschenkoartem/Tandem

ЖУРНАЛ И TURN В 0.3.1
В «Качество и сеть» есть «Открыть журнал», «Проверить TURN» и режим «Только TURN».
Журнал: logs/tandem.log в папке данных. Каждая запись — с новой строки со временем
и русским пояснением. Пароли, полные приглашения и игровые нажатия не записываются.
Для TURN получите iceServers у провайдера, вставьте их на обоих ПК, проверьте TURN,
сохраните настройки и создайте новые приглашение и ответ. После перезапуска клиента
TURN credentials нужно вставить заново. Инструкция:
https://github.com/lemeschenkoartem/Tandem/blob/main/deploy/TURN.md

ОТКЛИК И TAILSCALE В 0.4.0
Можно оставить Tailscale включённым: ручные приглашения теперь сохраняют его
маршруты по умолчанию. На обоих ПК должна быть 0.4.0. Создайте новые приглашение
и ответ после обновления. В «Качество и сеть» нажмите «Проверить путь Tailscale»
во время трансляции. Соберите 30–60 секунд движения в игре и нажмите
«Сохранить отчёт в файл». Нужны отчёты обоих ПК за одну и ту же попытку.
Отчёт показывает p95, отдельные составляющие задержки и подсказки. Он не измеряет
полную задержку управления и не доказывает отсутствие видимой пикселизации.
Режим «Только UDP» не отменяет возможный DERP внутри Tailscale.
https://github.com/lemeschenkoartem/Tandem/blob/main/deploy/PERFORMANCE.md
