# Tandem 0.2.0

[Скачать готовый Windows-клиент](https://github.com/lemeschenkoartem/Tandem/releases/download/v0.2.0/Tandem-0.2.0-Windows-x64.zip)
· [Релиз и инструкция](https://github.com/lemeschenkoartem/Tandem/releases/tag/v0.2.0)

Прототип для двух Windows 10/11 x64 ПК: трансляция монитора со звуком,
клавиатура/мышь с согласия владельца, смена ролей, аккаунты с постоянным ID,
а также прямое соединение с ручным обменом приглашением и ответом без VPN.

Полная инструкция: [START-HERE.txt](START-HERE.txt).

## В 0.2.0

- Относительная мышь и Pointer Lock: границы экрана не ограничивают камеру.
  В полном экране захват включается и для рабочего стола с виртуальным курсором.
  При потере захвата ввод приостанавливается и нажатия отпускаются.
- Ctrl+F12 выходит из полного экрана на стороне зрителя. Ctrl+Alt+F12 у владельца
  отзывает управление. Курсор скрывается в игровом режиме; видимость курсора хоста
  передаётся через GetCursorInfo без списков процессов или названий окон.
- HD 1280×720, профили 1080p/60, 1080p/120 и AV1, настройки с подтверждением.
  Профиль применяется к работающему отправителю; изменение со стороны зрителя
  запрашивает согласие хоста. Диагностика различает лимит и реальный битрейт.
- Ключи входа живут до 30 дней: сервер хранит SHA-256 токена, клиент — токен в
  Windows safeStorage/DPAPI. Пароли не сохраняются. При недоступном защищённом
  хранилище нет текстового fallback. Перезапуск и потеря WebSocket поддерживают
  восстановление входа; управление и трансляция автоматически не разрешаются.
- Прямой режим не требует сервера аккаунтов: offer и answer переносятся строкой
  или файлами `.tandem`. Владелец принимает ответ до просмотра экрана. После
  установления WebRTC дальнейшая сигнализация идёт по каналу данных. Приглашения
  не содержат пароль или ключ запомненного входа. Кандидаты известных VPN-диапазонов
  исключаются; для проверки отключите VPN и его выходной узел в ОС.

## Соединение

Для прямого режима выберите его в клиенте, создайте приглашение, отправьте файл
другу, получите ответ и примените его. STUN помогает пройти NAT, но не гарантирует
доступность при CGNAT/symmetric NAT. В сложных сетях нужен свой TURN. Публичного
сервиса регистрации и TURN автоматически не разворачивается.

Существующий режим общей сети работает через Tailscale/Radmin VPN или свой WSS
сервер. Запустите встроенный сервер на одном ПК, передайте полное приглашение,
зарегистрируйте два аккаунта на этом сервере. ID привязаны к его базе.

Обновите оба клиента до 0.2.0. Сервер использует handshake протокола 3. Миграция
SQLite добавляет таблицу токенов и сохраняет прежние аккаунты, хеши и ID.

## Качество и задержка

WebRTC/SRTP/DTLS, два канала ввода: надёжный для нажатий и ненадёжный для движений.
Мышь отправляется с независимым от FPS окна ограничением 250 событий/с;
Windows SendInput использует MOVE_NOCOALESCE. Видеопоток сохраняет разрешение
при нехватке ресурсов, может снижать FPS. Целевая буферизация видео/аудио минимальна.
Initial bitrate hint ускоряет начало потока; принудительного минимального битрейта
нет, чтобы не создавать очередь на медленном канале.

GPU не устраняет ограничение канала. Для RTX 50 имеет смысл сравнить аппаратный
AV1 с H.264; реальное аппаратное кодирование решает Chromium/драйвер. Показываются
encoderImplementation и powerEfficientEncoder, если они доступны, причина ограничения,
время обработки и параметры хоста у зрителя. Наличие карты само по себе не является
доказательством аппаратного кодировщика. Прямого NVENC SDK в этой версии нет.

Начните с 1080p/60 H.264 45 Мбит/с и Ethernet, затем сравните 1080p/120 H.264 65 Мбит/с
и AV1 45 Мбит/с. Снижение FPS даёт больше бит на кадр. Режимы 144–240 FPS экспериментальны.
Нет обещания достижения 4K/120, 240 FPS или конкретной задержки. Для уровня Parsec
на таких режимах может понадобиться нативный DXGI/WGC → NVENC/AMF/Quick Sync конвейер.

## Разработка и Windows-сборка

Node.js 24 LTS x64:

```powershell
npm ci
npm start
npm run check
npm test
npm run package:win
```

Результат: вся папка `release/Tandem-win32-x64`, включая `Tandem.exe` и ресурсы.
Готовый клиент не требует Node.js. Сборка не подписана сертификатом разработчика.
При cross-build на Linux поместите официальный `@koromix/koffi-win32-x64@3.3.7`
в `node_modules/@koromix/koffi-win32-x64`; Windows npm делает это автоматически.

Отдельный сервер: `npm ci --omit=dev`, `npm run server`; переменные `PORT` (8787),
`HOST` и `DATA_DIRECTORY`. Для публичного развёртывания требуется WSS, например
[deploy/Caddyfile](deploy/Caddyfile). Пример своего TURN —
[deploy/turnserver.conf.example](deploy/turnserver.conf.example).

## Проверка

`npm test` проверяет границы ввода, геометрию видео, SDP, профили, приглашения,
миграцию аккаунтов, токены, шифрование хранилища и работу сети. `npm run test:browser`
(Playwright, `CHROMIUM_PATH`, необязательный `TANDEM_TEST_ICE`) запускает два клиента
и реальные WebRTC-потоки canvas 1080p/HD, проверяет полноэкранный Pointer Lock,
Ctrl+F12, применение битрейта, перезапуск/восстановление входа, файлы прямой связи,
управление и смену ролей в обоих режимах. Ввод Windows в этих тестах заменён IPC-моком.

В управляемой Linux-среде Chrome запрещает прямой UDP: интеграционные проверки
выполнены через локальный TURN/TCP на loopback. Политика браузера не менялась.
Эти тесты не проверяют прямой маршрут между реальными NAT, Windows DPAPI,
захват/кодировщик GPU Windows или совместимость конкретной игры с SendInput.
Античит, Windows UIPI и повышенные права игры могут блокировать ввод.

`test/electron-smoke.cjs` отдельно проверяет загрузку настоящего Electron,
preload/IPC и встроенный сервер. После обновления на ваших ПК сравните фактический
кодек, ограничение CPU/bandwidth, битрейт при движении, FPS, потери и время обработки.
