# Tandem 0.4.0

[Windows x64](https://github.com/lemeschenkoartem/Tandem/releases/download/v0.4.0/Tandem-0.4.0-Windows-x64.zip)
· [Релиз](https://github.com/lemeschenkoartem/Tandem/releases/tag/v0.4.0)

Клиент для двух Windows 10/11 ПК: экран и системный звук, клавиатура/мышь с
согласия владельца, смена ролей. Оба пользователя могут быть хостами игры.

**Общий публичный сервис ещё не развёрнут.** В обычном интерфейсе больше нет
поля IP/адреса хоста и отдельного встроенного сервера. Для поиска по ID и друзей
нужна одна публичная служба Tandem. Клиент намеренно не содержит выдуманного
адреса: до её размещения работает резервный обмен прямыми `.tandem`-приглашениями.
Сервер готов к развёртыванию: [deploy/HOSTING.md](deploy/HOSTING.md).

## В 0.4.0: работающий путь Tailscale и качество

- Ручные приглашения по умолчанию сохраняют адреса Tailscale/Radmin, включая
  IPv6 Tailscale. Их исключение стало явной настройкой. Это позволяет использовать
  Tailscale с ручным обменом без отдельной службы аккаунтов.
- «Проверить путь Tailscale» в Windows проверяет выбранный IP потока командами
  официального tailscale.exe: status --json и пять ping. Отличает прямой путь
  от DERP, показывает медиану/p95. Служебный JSON, ключи и имена устройств
  не попадают в отчёт. Конфигурация Tailscale и Windows не меняется.
- Внутренний UDP WebRTC через Tailscale больше не выдаётся за доказательство
  прямого внешнего UDP. Режим «Только UDP» исключает TURN по TCP/TLS и TCP-кандидаты;
  внешний путь Tailscale всё равно проверяется отдельно.
- Понятный текстовый отчёт за последние 60 секунд: RTT, потери, кодирование,
  декодирование, очередь, буфер/сетевой минимум, зависания, повторные передачи,
  QP. Показывает медиану/p95, не заменяет отсутствующие значения нулевыми,
  сбрасывает смешение разных маршрутов/кодеков/ролей. При доступной метаинформации
  браузера отдельно измеряется время от последнего пакета кадра до композитора.
  Полная задержка нажатия до изображения здесь не измеряется.
- В авто добавлена консервативная эвристика для H.264: при устойчивом QP >=35,
  достаточном реальном FPS и достигнутом лимите скорости уменьшается FPS, чтобы
  оставить больше данных на кадр. После изменения FPS удерживается 30 секунд
  перед повышением. Это не измеритель видимой резкости и не гарантия отсутствия
  пикселизации; QP других кодеков с этим порогом не сравнивается.
- [Как проверить ваш маршрут и сравнить качество](deploy/PERFORMANCE.md).

## Журнал и TURN (добавлены в 0.3.1)

- Читаемый журнал UTF-8: одна строка на событие, время с часовым поясом, уровни
  ИНФО/ВНИМАНИЕ/ОШИБКА и русские пояснения. Кнопка «Открыть журнал», ограниченная
  ротация (5 МиБ + 3 предыдущих). Асинхронная запись, сводка потока раз в 10 секунд;
  игровые нажатия, движение мыши, пароли, токены и полные приглашения не пишутся.
- Отдельные записи для приглашения, ответа, разрешений, ICE/STUN/TURN, сетевого
  состояния, качества, действий интерфейса, входа/друзей и сбоев приложения.
- «Проверить TURN» проверяет реальное выделение relay-кандидата; режим «Только TURN»
  не допускает незаметного перехода на прямой путь. Нет встроенного публичного TURN:
  требуются адрес и credentials вашего провайдера. [Инструкция](deploy/TURN.md).
- Таймер ручного обмена отделён от таймера соединения: 15 минут на файлы, затем
  до 45 секунд после применения ответа хостом. Истечение ожидания ответа больше
  не выдаётся за установленную проблему NAT. Подпись кнопки меняется при импорте.

## Что изменилось

- Автоматическое качество включено по умолчанию. Выбранные разрешение, FPS и
  битрейт задают верхние пределы. Начало — до 1080p/60 и 30 Мбит/с, затем повышение
  при стабильной связи. По умолчанию разрешение не падает ниже Full HD; можно
  разрешить HD. Пользовательский HD остаётся HD. Есть ручной режим.
- Раз в секунду оцениваются потери, RTT относительно нормального для маршрута,
  доступная полоса, рост очереди, время кодирования/декодирования и пропуски кадров.
  Данные зрителя передаются хосту с привязкой к текущему потоку и сроком свежести.
  Перегрузка быстро снижает битрейт; устойчивая нехватка ресурсов снижает FPS,
  затем разрешение до выбранного минимума. Восстановление медленное, с паузами.
  Постоянный A/V-буфер Chromium не принимается за растущую перегрузку сети.
- Авто начинает с H.264. H.265/AV1 пробуются только при совместных положительных
  RTC/MediaCapabilities-проверках encode/decode с smooth/powerEfficient. Это подсказка
  браузера, не доказательство NVENC. При перегрузке обработки возврат к H.264.
  Смена кодека может дать краткий перерыв; точные режимы зависят от Windows/Chromium.
- Поиск аккаунта по ID, входящие/исходящие заявки, принятие/отклонение, удаление,
  локальная копия друзей, онлайн-статусы. Запрос просмотра не требует предварительного
  создания комнаты: друг подтверждает его и выбирает монитор. Дружба не разрешает
  просмотр и управление автоматически. Есть отмена и таймаут заявки на просмотр.
- `settings.json`, `friends-<network>-<id>.json` и `account.json` в папке данных клиента.
  Настройки и друзья мигрируют из прежнего хранилища при сохранении/входе.
  Кнопка «Открыть папку данных» показывает эти файлы. Онлайн-статусы не сохраняются
  как будто они всё ещё актуальны. Список изолирован по аккаунту и общей службе.
- Пароль не сохраняется; 30-дневный ключ входа шифруется Windows DPAPI/safeStorage
  в `sessions.enc`, сервер хранит его SHA-256. При недоступном защищённом хранилище
  нет текстового fallback. Явный выход отзывает ключ. TURN-пароль в текущей версии
  не записывается в открытый JSON и действует только в текущем запуске.
- Установленный поток и смена ролей работают по P2P-каналу данных даже при потере
  WebSocket службы. Вход/список восстанавливаются отдельно, без прекращения игры.
- Сохранены относительная мышь, полный экран с захватом по краям, Ctrl+F12 для
  выхода, Ctrl+Alt+F12 у владельца для отзыва, HD–4K, режимы 60–240 FPS.

## Соединение и сравнение с Parsec

По опубликованной документации Parsec, Signal API и STUN помогают участникам
обменяться адресами и пройти NAT; видео обычно передаётся напрямую по UDP.
Их закрытый BUD и нативный zero-copy GPU-конвейер не являются настройками,
которые можно скопировать в WebRTC.

- [Архитектура и последовательность соединения Parsec](https://support.parsec.app/hc/en-us/articles/32361410290324-Components-and-Connection-Sequence)
- [BUD, динамический битрейт и обработка на GPU](https://parsec.app/technology)
- [Метрики и изменение битрейта при перегрузке](https://support.parsec.app/hc/en-us/articles/32381603663636-Stream-Overlay-Stats-and-Logging)

Tandem использует собственную политику качества поверх стандартного WebRTC
congestion control: без принудительного минимального битрейта и без загрузки
канала тестовым потоком. Прямой UDP предпочтителен; STUN не гарантирует обход
symmetric NAT/CGNAT. При сложном NAT нужен свой TURN. VPN не требуется для обычного
поиска после размещения общей службы, но качество определяется реальным маршрутом.
Диагностика показывает P2P/TURN и транспорт; P2P может проходить по VPN-интерфейсу,
если он активен. Сервер аккаунтов не обрабатывает игровой видеопоток.

GPU ускоряет обработку видео, но не исправляет сетевые потери/плохой маршрут.
Прямого NVENC SDK или нативного DXGI/WGC → NVENC конвейера пока нет. Нельзя
обещать задержку или качество Parsec одними пресетами, 4K/120 либо 240 FPS.
RTT — только сеть туда и обратно, не измерение полной задержки управления.

## Использование

После размещения службы: войдите, откройте «Друзья», найдите ID друга, отправьте
заявку и дождитесь принятия. Нажмите «Подключиться» у друга в сети. Он подтверждает
просмотр и выбирает монитор. Управление запрашивается отдельной кнопкой.
Оба клиента нужно обновить до 0.4.0. Старые локальные серверы имели отдельные базы
аккаунтов; их ID не становятся глобальными автоматически.

До размещения службы: на странице игры раскройте «Прямая связь по приглашению».
Хост создаёт файл предложения, друг открывает его и возвращает файл ответа.
Хост открывает ответ и подтверждает подключение. Для отдельного сравнения без VPN отключите его после проверки текущего пути; при заблокированном NAT настройте свой TURN. Аккаунт в этом режиме не нужен.

Оставьте авто с пределами 1080p/120/60 Мбит/с, кодек «Авто». Для сравнения есть
ручные H.264 и AV1. Ethernet на обоих ПК обычно стабильнее Wi-Fi. Проверьте
фактический FPS, обработку на хосте/клиенте, потери и выбранный транспорт.

## Разработка

Node.js 24 LTS x64:

```sh
npm ci
npm run check
npm test
npm start
npm run package:win
```

Сервер: `npm run server`, переменные PORT/HOST/DATA_DIRECTORY. В разработке клиенту
можно передать `TANDEM_SERVICE_URL=ws://127.0.0.1:8787`. В продакшене только WSS.
Развёртывание и постоянные тома: [deploy/HOSTING.md](deploy/HOSTING.md).

Windows-сборка содержит всю папку `release/Tandem-win32-x64`, включая ресурсы и
распакованный Koffi `.node`. Node.js на игровых ПК не нужен. Для cross-build нужен
официальный `@koromix/koffi-win32-x64@3.3.7`; Windows npm устанавливает его сам.
Сборка не подписана сертификатом разработчика.

## Проверки и ограничения

`npm test`: ввод, геометрия, SDP, токены, JSON-хранилище, дружба/офлайн-заявки,
согласие на просмотр и адаптивная политика (перегрузка, восстановление, пределы,
CPU/decoder, устаревшие/сброшенные счётчики). `npm run test:browser` проверяет два
клиента, настоящий 1080p/HD WebRTC-поток, файлы друзей, переподключение, согласие,
ввод, полный экран, ручное/автоматическое качество и смену ролей. Перегрузка в
интеграционной проверке задаётся подстановкой статистики RTT в работающий поток;
это не замер реального интернет-канала. `test/electron-smoke.cjs` проверяет настоящий
Electron, preload/IPC, сервер, файлы и нативное событие Ctrl+F12.

В управляемой Linux-среде действует запрет прямого UDP в Chromium. Проверки идут
через loopback TURN/TCP без изменения политики. Реальные NAT, Windows GPU/NVENC,
DPAPI и ввод в конкретной игре требуют проверки на ваших ПК. Античит, Windows UIPI
и повышенные права могут блокировать SendInput. Геймпады пока не поддерживаются.
